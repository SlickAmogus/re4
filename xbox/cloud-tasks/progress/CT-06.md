## Findings
- Task text says "high nibble = scale exponent, low nibble = coef index"; dspadpcm.h says the opposite
  (low nibble = scale, high nibble = coef pair index). The header matches Dolphin/libogc/vgmstream
  (scale = 1 << (ps & 0xF), coef = (ps >> 4) & 7). Keeping the header's convention.

- Xbox ADPCM block model (decided): per channel 36 bytes = {s16 predictor = sample 0 verbatim, u8 step
  index, u8 0} + 32 bytes = 64 nibbles, of which 63 carry samples 1..63 and the last is padding (0).
  Matches XDK CImaAdpcmCodec (wSamplesPerBlock = 64) and vgmstream decode_xbox_ima. Low nibble first.
  Stereo: both headers (L,R = 8 bytes) then 4-byte words alternating L,R (8 nibbles each). IMA expand
  uses the bitwise reference form (step>>3 + conditional step, step>>1, step>>2), as the Windows ACM
  IMA codec and vgmstream do (NOT ffmpeg's ((2d+1)*step)>>3).
